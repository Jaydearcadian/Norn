# Norn contributor instructions

- Preserve the canonical product language: Norn Profile, Feed, Score, Gaps, Pack and Watch.
- Never promote a `claimed` or `aspirational` capability to `verified` without a linked evidence record.
- Keep the paid ASP outcome bounded to one Opportunity Brief call.
- Keep application submission outside the automatic service path; approval is mandatory.
- Payment, input schema, replay safety, claim status and terminal state are deterministic boundaries.
- Never log or return payment signatures, API credentials, private keys or reusable authorisation.
- Update lifecycle evidence after material implementation, deployment or marketplace changes.
